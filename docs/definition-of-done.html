Project Structure SOP

Definition of Done

A lightweight bar for "structurally done" — ready to move into formal QA. The exhaustive checks live in the QA and Go-Live checklists.

A build is structurally done when…

  • All required pages exist, and all in-scope optional pages from the brief exist. See Required Pages.
  • Every page follows the Client-First core structure — no ad hoc div structures. See Naming Conventions.
  • All components/sections follow the folder and naming conventions — no unnamed Div Block classes, no leftover Webflow default names.
  • CMS collections match the naming and field conventions, and a CMS Collections summary exists in the hand-off notes.
  • All images/assets are renamed and optimized for size.
  • The Style Guide page reflects the components actually used in the build.
  • No orphaned pages, unused symbols, or leftover placeholder sections remain in the project.
  • The project is ready to be handed to QA, and once QA passes, to Go-Live. See QA & Go-Live Connection.
Not a substitute: "done" here means structurally ready for review — it does not mean QA has passed or Go-Live is complete. Don't skip either checklist because this list is satisfied.
