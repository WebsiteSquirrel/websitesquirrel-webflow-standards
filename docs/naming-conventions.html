Project Structure SOP

Folder & Naming Conventions

Client-First gives us the naming grammar. This page defines how WebsiteSquirrel applies it to pages, CMS collections, components, and assets so every project looks the same.

Reference: full rationale for the class system lives at Client-First — Classes strategy and Client-First — Folders strategy. This page is the condensed, WebsiteSquirrel-specific version.

General naming rules

Apply these everywhere — pages, collections, components, assets.

  • All lowercase, words separated by hyphens: home, about-us, case-study.
  • No abbreviations or shorthand unless it's an industry-standard term (faq, cta). A new dev, a QA tester, or the client should understand the name with zero context.
  • Underscore (_) is reserved for Client-First folder syntax: folder-name_element-name (e.g. testimonial-slider_arrow). Never use it as a generic word separator.
  • Combo/variant classes always use the is- prefix: is-active, is-dark, is-mobile-only.
  • Name by function, not by visual position or one-off content: pricing-cards, not three-boxes-with-price; team-list_headshot, not round-image.

Pages

Page names in the Webflow Pages panel and their slugs follow the same lowercase-hyphenated pattern. Use folders inside the Pages panel to group families of pages once a site has more than a handful.

WhatConventionExample
Static page name / sluglowercase-hyphenated, matches URL/about-us, /case-studies
CMS template page slugsingular collection name as the folder, dynamic slug field drives the URL/blog/{slug}, /case-study/{slug}
Utility / system pagesprefixed so they sort together and read as non-production401-password, 404-not-found, style-guide
Page folders (Pages panel)group by section of the site once > 6–8 pages existCompany/, Resources/, Legal/
Keep it aligned: the Webflow page name and slug should match (page name "Case Studies" → slug case-studies). If they diverge, note the slug in the page's Notes so QA can find it fast.

CMS Collections

Collections are named as singular nouns (Webflow pluralizes them for Collection Lists automatically). Field names follow the same clarity-first rule as classes — describe what the field holds, not its type.

WhatConventionExample
Collection nameSingular, Title Case in the DesignerBlog Post, Team Member, Case Study, Service
Collection slugauto-generated plural-hyphenated; verify it reads cleanlyblog-posts, team-members, case-studies
Field namesplain English, no type suffixes (no "nameText")Featured Image, Publish Date, Excerpt, Author
Reference fieldsname after the related collection; singular for Reference, plural for Multi-referenceAuthor (Reference → Team Member), Related Posts (Multi-ref → Blog Post)
Option fieldsoption values in Title Case, short and finiteStatus: Draft / In Review / Published
  • One collection = one clearly defined content type. If two collections are only ever used together, consider whether one should be a field on the other instead.
  • Keep a short CMS Collections list in the project's hand-off notes: collection name, purpose, and which pages consume it.

Components & sections

We follow Client-First's Core Structure and Folders systems exactly. Every page uses the same six-layer skeleton, and every reusable group of elements sits inside a named folder so it's identifiable in the Navigator.

Core structure — every page

LayerClassPurpose
1. Page wrapperpage-wrapperOutermost div; wraps everything on the page
2. Main wrappermain-wrapper<main> tag; wraps all content sections, excludes nav/footer
3. Sectionsection_[identifier]One <section> per content block, named for the Navigator (e.g. section_hero)
4. Global paddingpadding-globalControls left/right page padding only
5. Containercontainer-[size]Centers content, sets max-width (small / medium / large)
6. Section paddingpadding-section-[size]Controls top/bottom section spacing (small / medium / large)

Folder & component naming

  • Reusable, project-wide component → keyword-based folder, no page name: slider_arrow, pricing-card_price.
  • Add a _component suffix on the outer wrapper only when the folder is a complete, copy-pasteable UI block: pricing-card_component, newsletter-signup_component.
  • One-off, page-specific block → page name as the folder: about-hero_image, careers-cta_button. Rule: if it's page-named, it stays on that page only.
  • Small variation of an existing global component on one page → keep the component's folder, add the context as the first keyword: slider_testimonials-arrow (not a new folder).
  • Use a combo class (is-) instead of a new folder whenever the change is a simple style variant: card is-featured, section_cta is-dark.
  • Name sections descriptively so the Navigator reads like a sitemap: section_hero, section_logos, section_how-it-works, section_testimonials, section_pricing, section_faq, section_cta.

Assets

Asset file names should survive being downloaded, re-uploaded, or handed to another tool without losing meaning.

Asset typeConventionExample

Iconsicon- prefix + concepticon-arrow-right.svg, icon-chevron-down.svg

Don't skip this: never rely on Webflow's auto-generated upload names (image-1234.png). Rename before or immediately after upload, and compress/size images correctly — see the Go-Live checklist's performance checks.
