Project Structure SOP

Component & Section Organization

How sections are named, when to reuse an existing component, and when a new one is actually warranted.

Reuse before you rebuild

  • Before creating a new component, search the Navigator / Style panel for an existing folder that already does the job (search "card" before building a fourth card variant).
  • If an existing component is 80%+ right, extend it with a combo class (is-) rather than duplicating the whole structure.
  • Only create a genuinely new component folder when the structure or purpose is meaningfully different — not just a color or spacing change.

Section naming = page outline

Name every section_[identifier] so scrolling through the Navigator top-to-bottom reads like an outline of the page. Anyone — including the client — should be able to open the Navigator and understand the page without opening the canvas.

Avoid deep stacking

Per Client-First: don't stack more than a couple of classes on one element. If you find yourself combining three or more utility classes to achieve one look repeatedly, create a custom class for it instead. This keeps hand-off and QA fast — a reviewer can select an element and immediately see one or two meaningful class names, not a stack of five utilities.

Why it matters: deep-stacked classes can't be reordered in the Designer Styles panel, which slows down edits — especially at non-base breakpoints. See Client-First — Classes strategy for the full rationale.
